# SAM (Altyn Sauda)

Веб-приложение (PWA) для учёта партий фруктов: партии, продажи, покупатели, оплаты, расходы, отчёт. Чистые HTML/CSS/JS, без сборки и зависимостей.

## Запуск

```
python3 -m http.server
```

Открыть http://localhost:8000. С `file://` не работают шифрование (вход по паролю) и service worker.

## Структура

```
index.html              разметка, диалоги, подключение скриптов
sw.js                   service worker (кэш, офлайн); лежит в корне, чтобы охватывать весь сайт
manifest.webmanifest    манифест PWA
css/
  style.css             все стили
js/
  config.js             локальный sheetId (в .gitignore, не коммитится)
  app-config.js         публичные настройки: Google Client ID
  gsheet.js             вход через Google и личная Google Таблица пользователя
  auth.js               регистрация и вход (локальные аккаунты, пароль как PBKDF2-хеш)
  deals.js              заявки на согласие (Firebase Auth и Firestore), ES-модуль
  app.js                основная логика: вкладки, диалоги, отчёт, синхронизация, языки
assets/                 иконки приложения
firebase/
  firestore.rules       правила Firestore для коллекции deals
```

Порядок подключения в `index.html`: `config.js`, `app-config.js`, `gsheet.js`, `auth.js`, `deals.js` (module), затем `app.js`.

## Разделы приложения

- **Партии**, **Продажи**, **Покупатели**, **Отчёт** (итоги, партии за период, разбивка расходов, таможня).
- Оплаты (Kaspi, наличные, под реализацию), расходы, курс $/€, номера WhatsApp, накладная (PDF), резервная копия.
- Языки интерфейса, тема и акцентный цвет, режим вида: авто, телефон, компьютер.

## Где хранятся данные

- Учёт: `localStorage` браузера и личная таблица «Altyn Sauda» на Google Диске пользователя (часовой пояс Asia/Almaty). Права только `drive.file`: приложение видит лишь файл, который создало само.
- Резервная копия: Настройки → «Скачать копию».
- Заявки на согласие по товару «под реализацию»: общая база Firestore (проект `altyn-sauda-d5a70`).

## Вход

- **Через Google**: `googleClientId` в `js/app-config.js`. Пока он пустой, работает только локальный вход по паролю.
- **Локальный**: аккаунты в браузере, пароль хранится как PBKDF2-хеш.
- Для заявок используется отдельный вход Firebase (Google). Домен сайта должен быть в Firebase: Authentication, Settings, Authorized domains.

## Правила Firestore

Файл `firebase/firestore.rules` нужно опубликовать вручную: Firebase Console, Firestore Database, Rules. Правила проверяют набор полей, `email_verified`, `root` и время (`request.time`). Изменение файла в репозитории само по себе ничего не меняет в консоли.

## Кэш и обновления

Версия кэша service worker задаётся константой `V` в `sw.js`. Меняйте её при каждом изменении списка файлов или их содержимого. При добавлении или перемещении файлов обновляйте массив `FILES` в `sw.js`.

Ключи Google Client ID и Firebase `apiKey` не секретны. Доступ к данным защищают правила Firestore и права `drive.file`.
